# 训练操作优化设计（待确认）

用户选择：优化训练操作，重点为数据检查、进度曲线、模型选择。

## 方案与范围

推荐在当前 PySide6 模型训练页内增加操作面板，保持已确认的侧边导航和视觉样式。相比增加独立训练向导窗口，这种方式切换更少、状态更集中；相比独立训练平台，不引入服务、账号或新的数据管理系统。具体实现方案为本次提案，待用户确认。

沿用现有 train/predict 接口、1D-CNN、学习率、数据划分及早停策略；本次不调整网络结构、比较模型精度、加入 GPU 配置、暂停恢复或训练任务数据库。

## 操作流程

1. **选择与检查数据**：浏览 NPZ 后可点击“检查训练数据”。后台复用实际训练所用的 load_pairs 校验，显示文件名、样本数、时间门数、深度层数，以及时间 / 深度范围和标注电阻率范围。补齐时间轴与深度轴的有限值、合法范围检查；时间严格大于零、深度不小于零，二者严格递增。格式、维数、缺键、NaN/Inf 或无效数值直接说明原因。校验功能不依赖 PyTorch；数据路径变化后清除旧检查结果。训练启动时仍由训练函数重新验证文件，不能用旧检查绕过校验。
2. **配置与训练**：提供模型保存前缀的文件选择器，以及现有轮次设置。缺少 PyTorch 时明确解释原因，允许检查数据和查看模型元数据。后台训练仍保持任务互斥与关闭保护。
3. **监控训练**：显示当前轮次 / 最大轮次、训练 MSE、验证 MSE、当前最佳验证 MSE，并实时更新两条损失曲线。曲线明确为归一化对数目标空间的 MSE，不是水害识别准确率。运行中使用真实轮次进度；早停后显示实际完成轮次与最佳验证损失，不伪装为训练到最大轮次。未开始时展示空状态。
4. **选择模型用于推理**：通过“选择已有模型”选择 .pt，自动匹配同名前缀的 _metadata.npz。后台校验元数据与配套文件存在性，显示时间门数、深度层数和轴范围；只读取安全 NPZ 元数据，不为展示信息而反序列化 .pt。缺少配套文件或轴不合法给出明确提示。可选历史 CSV 缺失不影响模型使用。训练成功后自动定位刚生成的模型，保留当前测线成果；真正推理时沿用现有时间门匹配和质量拒绝规则。

## 状态与兼容

- 数据检查、模型检查与计算 / 训练 / 导出共用任务互斥。失败结束后恢复控件，不清除之前可用的测线数据和结果。
- 当前后台任务增加结构化训练进度信号，保留日志文字。绘图、进度控件和数据摘要只在主线程更新。
- 不改既有 CSV/NPZ/JSON 模型输出文件命名、旧数据格式、CLI 或默认物理公式。
- 小窗口中的训练页继续可滚动；损失曲线为单独卡片，不挤压路径选择和主要按钮。
- 示例 NPZ 明确标记为均匀半空间教学数据，不能作为现场水害识别能力的证据。

## 验证与交付

新增边界测试验证数据及模型元数据检查，离屏 GUI 测试验证检查结果、路径变化失效、真实轮次信号和曲线、模型浏览自动匹配、错误恢复、训练成功后当前测线成果保留。基础检查必须在未安装 PyTorch 时通过；实际训练与推理只有在依赖可用并实测后才宣称通过。提供更新后的源码 ZIP、训练页截图和中文变更记录。Windows 原生、高 DPI、GPU 和现场数据效果不在本轮验收范围。
