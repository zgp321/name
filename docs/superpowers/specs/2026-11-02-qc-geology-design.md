# 质量诊断与地质/钻孔联合解释设计

## 目标

在现有 TEM 结果页中增加两个可追溯的辅助工作台：

1. 质量诊断：把处理结果中的时间门 QC 标记整理成测点级统计、拒绝原因统计和时间门状态矩阵，并查看单个测点的原始/质控后衰减曲线。
2. 地质/钻孔联合解释：导入带深度区间的钻孔/岩性表，在 TEM 伪剖面上叠加钻孔位置和区间，生成与低阻候选区的几何关联表。

两者都只解释已有结果，不修改原始观测和处理结果。所有关联都明确标为辅助证据或伪深度几何对照；不能把低阻候选区或外部 `water_evidence` 字段自动变成含水结论。

## 交互布局

结果页保留现有图表和候选异常表，在其下增加 `QTabWidget`：

- `质量诊断`：质量摘要卡、拒绝原因表、测点 QC 汇总表、测点选择框、选中测点衰减曲线。
- `地质 / 钻孔联合`：导入 CSV/TXT/XLSX 按钮、表格预览、联合伪剖面图、候选-钻孔空间关联表。

不增加侧边导航项，保证现有四步工作流和外部调用者的导航索引兼容。

## 数据契约

钻孔/岩性导入表的必需字段：

`line_id,borehole_id,x_m,y_m,elevation_m,depth_top_m,depth_bottom_m,lithology`

可选字段：`water_evidence,confidence,notes`。中文别名由独立的 `geology.py` 适配；缺失 `line_id` 时使用 `L1`，缺失 `y_m/elevation_m` 使用 0，但不会猜测深度或单位。

验证规则：标识非空、坐标和深度有限、`0 <= depth_top_m < depth_bottom_m`、同一钻孔区间不交叠（端点相接允许）、`confidence` 若存在则在 `[0,1]`。所有失败都返回可读错误。

## 计算规则

`quality.py` 只接受 `Result.readings` 的现有字段，按 `station` 生成：总/有效/拒绝门数、有效率、SNR 中位数与最小值、首尾有效时间、QC 原因计数。时间门矩阵保留每个门的原始 `qc` 字符串，不填补缺失。

`geology.py` 生成：

- 钻孔与候选异常的几何关联：X 距离、伪深度区间重叠、岩性和外部证据原样复制；
- 默认 X 容差为相邻 TEM 测点中位间距的一半；没有有效测点时不生成关联；
- 关联文案使用“伪深度几何对照/待人工复核”，不输出“含水/不含水”分类。

## 导出

在现有成果目录增加 `qc_station_summary.csv`、`qc_gate_summary.csv`、`boreholes.csv`（若已导入）和 `borehole_candidate_links.csv`（若有结果）。`manifest.json` 增加 `quality_diagnostics` 与 `geology_overlay` 摘要，不改变既有文件字段和图像。

## 边界

- 不把钻孔深度强行校正为真实地下高程；伪剖面与钻孔区间仅作几何对照。
- 不建立地层连续面、不做二维/三维反演、不自动确认含水。
- 不在后台线程中操作 Qt 控件；导入、计算和导出沿用现有 Task 生命周期。
